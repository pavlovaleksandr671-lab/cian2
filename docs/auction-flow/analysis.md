# Аукцион квартиры: сценарии и аналитика

Карта: `public/auction-flow/index.html` → `/auction-flow/index.html`. Снимок 23.11.2026, исходный коммит `2546d66`, 32 реальных скриншота. Настройка мобильного viewport 390×900; JPEG среды браузера 375×865. Основной интерфейс и логика не изменены. Аналитические события предложены, но не подключены.

## Источники и метод

Изучены `src/pages/AuctionPage.tsx`, `auctionModel.ts`, CSS, README и документация. AGENTS.md отсутствует в проекте и родителях; правил аналитики и трекера в авторских исходниках/документации не найдено. Исходный неизменяемый UI-kit не трактуется как инструкция по продуктовой аналитике. Скриншоты получены в браузере через существующие видимые элементы управления, включая демо-панель. DOM и состояние React для съёмки не подменялись. Метаданные — `public/auction-flow/screens/captures.json`.

## Пользовательские сценарии

Продавец: S01 → S02 → S04 → S05 → S06 → S07 → S08 → S09. Ошибка цены S03 возвращает в S02; из проверки можно вернуться к настройке, из настройки — в объявление. После публикации параметры неизменяемы. Окончание: со ставками (S08/S11) или без них (S10). Контакт доступен только при наличии ставки.

Покупатель: B01/B02 → B03 → B06 → B07 → B08 → B17 → B18. Ошибки формата B04 и минимума B05; ошибка отправки B09 → повтор B10 → принятая ставка. Чужая ставка переводит в B11, откуда можно повысить. Завершение: победа B17, проигрыш B12, не участвовал B15, ставок нет B16. До публикации — B13 с переходом к демо B14.

Общие: C01 правила, C02 фото/избранное, C03 демо-панель. Диалоги закрываются крестиком/Escape/кнопками «Всё понятно» или «Готово»; во время pending закрытие блокируется. Клик по backdrop не реализован. Переключатель ролей сохраняет общий аукцион и экран продавца; в pending заблокирован. «Посмотреть как покупатель» открывает ту же карточку. Сброс возвращает в seller/listing и draft; панель details может остаться раскрыта. При обновлении страницы сбрасывается всё.

Обычный аукцион: старт 12 млн ₽, шаг 100 тыс. ₽, 24 часа; выбор шага 50/100/200 тыс., длительности 24/72/168 ч. Первая ставка ≥ стартовой; следующие ≥ текущая + шаг (не обязательно кратны шагу). Демо-пример начинает с тремя чужими ставками и максимумом 12,3 млн ₽. Окончание по времени вычисляется локально; кнопка завершения — только демо.

## Контракт событий

- Нейминг: auction_<объект>_<действие/результат>, lower_snake_case. Это предлагаемое правило, не стандарт production-аналитики Циана.
- Общая схема: schema_version=1, event_id (UUID), occurred_at (UTC ISO 8601), session_id, run_id, flow_id, actor_id (псевдоним, если доступен), role=seller|buyer, screen_id, screen_state, previous_screen_id, listing_id, auction_id (null до публикации), auction_status=draft|active|ended, auction_state_version, environment=prototype|production, is_demo, entry_point. Сейчас эти идентификаторы и события не реализованы.
- Все текущие прогоны environment=prototype и is_demo=true. Отдельно source=user|demo_control|timer. Демо-переключение ролей и искусственные ставки не смешивать с реальным спросом. Для продуктовых метрик фильтр environment=production и is_demo=false; здесь данных для него нет.
- Ставка: bid_flow_id на открытие формы; logical_bid_id на намерение с фиксированной суммой; новый logical_bid_id при её изменении. attempt_id уникален на каждую отправку/повтор; retry сохраняет logical_bid_id и увеличивает attempt_number. bid_id присваивается принятой ставке. Время ожидания считать по каждой попытке.
- Дедупликация по event_id; accepted — дополнительно по bid_id; published и ended — один раз на auction_id + версию перехода. Отказ локальной валидации не считается отправкой. Submit и retry взаимоисключающие для одной попытки.
- screen_view фиксирует вход/смену состояния, не каждую секунду таймера. Для status/history/result использовать порог видимости ≥50% в течение ≥1 с и дедуп по сессии + роли + auction_id + состоянию/версии. B01/B02 — один экран с разной прокруткой; S04/S05 — один экран с разным согласием.
- Денежные параметры — целое число RUB, сроки — часы, latency_ms — миллисекунды, пустой результат — final_price=null. Не передавать произвольный ввод, адрес, имя, контакты, текст ошибки, скриншоты и точную геолокацию. error_code — фиксированный enum.
- В рабочем продукте факты published/accepted/outbid/ended подтверждает сервер; UI отправляет только действия и просмотры. В прототипе их можно было бы брать из reducer и callback. Серверные события не добавлены в рамках этой задачи.

## Отсутствующие состояния и ограничения

### Загрузка и ошибка публикации · Нет в прототипе

Опубликовать сразу переводит аукцион в active. Нет сетевого запроса, pending, отказа, повтора или восстановления публикации.

### Сохранённый черновик и возврат в аукцион · Нет в прототипе

Данные живут в useReducer/useState и теряются после обновления страницы. Нет авторизации, списка аукционов, открытия по id и восстановления прерванной ставки.

### Новый аукцион после завершения · Нет в прототипе

В пустом результате есть текст о новом аукционе, но пользовательской кнопки перезапуска нет. Только учебный «Начать заново».

### Реальная коммуникация · Нет в прототипе

Нет отправки сообщения, звонка, платежа и юридического оформления. Оба диалога контакта — конец учебного сценария.

### Аукцион завершился при открытой форме · Защита в коде

bidError повторно вызывается при проверке, перед отправкой и через 1,4 с при ответе. Есть текст ended и блокировка. Случай не снят: минимальный срок 24 ч, а демо-панель недоступна под модальным диалогом. Внешний конкурент и естественное истечение требуют отдельного длительного/интеграционного прогона без подмены UI.

### Минимум вырос во время подтверждения · Защита в коде

Повторная проверка предотвращает устаревшую ставку и возвращает к вводу с актуальным минимумом. Через текущий видимый UI невозможно добавить конкурента под открытым dialog; отдельного скриншота гонки нет.

### Пустая история после окончания · Наблюдение

S10/B16 показывают «Первая ставка ещё впереди», хотя торги закончены. Зафиксировано без исправления интерфейса.

### Разный текст результата продавца · Наблюдение

Пояснение «Лучшее предложение получено» зависит от отсутствия yourBid, хотя продавцу собственная ставка не принадлежит. Поэтому отдельно показаны S08 и S11. Логика сохранена.

### События предложены, сбор не подключён · Ограничение аналитики

SDK, трекера и правил нейминга в авторских src/docs/tasks/team не обнаружено; AGENTS.md в проекте и родителях отсутствует. Карта и таблица — спецификация, метрики не измерены.

### Остальные отсутствующие состояния · Граница задачи

Нет отмены аукциона, редактирования после публикации, отзыва ставки, загрузки/ошибки карточки, пагинации истории, push-уведомлений и состояния офлайн. Они не добавлялись и не выданы за существующие экраны.

## Чтение карты

Стрелки показывают действия или изменения состояния. Пунктир — возврат, смена роли, демо или альтернативная ветка. Уведомления и прокрутка не превращены в выдуманные маршруты. Варианты S08/S11 зависят от состава ставок. Длинные временные ветки показывают итоговый UI, воспроизведённый кнопкой демо, а не ожиданием 24 часов.

Страница не подключается к аналитическим сервисам и работает без CDN. На карте доступны масштаб, перетаскивание, переход к роли, реестр экранов и просмотр оригинального скриншота. Таблица событий, метрики и ограничения доступны вкладками той же страницы.

Запуск: `npm run dev -- --port 5176`, затем `http://127.0.0.1:5176/auction-flow/index.html`. Можно открыть `public/auction-flow/index.html` напрямую: все ресурсы карты относительные. Исходники UI-kit не изменены.
